## Technical Decisions
- **Architecture**: Modular kernel — `src/security/`, `src/kernel/`, `src/control_plane.rs`, `src/swarm/`, `src/cortex/`
- **Database**: SQLite via rusqlite (bundled). `cp_*` schema is the sole source of truth. Legacy tables are read-only cache.
- **Control Plane**: `cp_daemon_snapshot()` = single-call operational view. `cp_scheduler_list_ready()` = canonical task scheduler.
- **Security Kernel**: 4 layers — Filesystem Jail → Policy Manager → Verify Chain (hash-chained audit ledger) → Egress Filter
- **Policy**: `raios-policy.toml` is the single security config source. `confirm` = fail-closed (deny) in daemon/stdio mode.
- **Egress**: Filtered at MCP tool hook level (not OS network layer — scoped to what raios controls).
- **Hash Chain**: Tamper *detection*, not prevention — correctly classified as forensic tool.
- **IPC**: VS Code extension proxies requests to daemon (port 42071) via Bearer token — token never exposed to WebView.
- **Critical Notes**: New work must read/write through `cp_*` functions in `src/db.rs`. Never write directly to legacy tables.

- Situation: scheduled automation reports success while its dependency output is unavailable. Signal: logs contain report-file, DNS, or stdin/prompt errors immediately before a success/notification line. Response: treat the run as failed or degraded, surface the root cause, and avoid publishing empty delivery. Expected payoff: trustworthy Raios notifications and actionable scheduled-job status.
- Situation: a desktop tray polls local APIs and repository state. Signal: refresh executes blocking HTTP or git work on Qt's UI thread, or it reads a legacy compatibility cache. Response: use authenticated canonical APIs and collect blocking work in a bounded background executor; render a bounded window of results. Expected payoff: responsive UI that reflects the control-plane source of truth.
- Situation: a tray settings UI persists a shared config. Signal: the serializer has an allowlist of known keys. Response: merge and preserve unknown top-level and nested sections, then test round-trip keys before saving. Expected payoff: prevent silent loss of future config domains such as bootstrap or factory.
- Before pruning existing recovery backups, fsync and directory-sync the verified replacement snapshot and checksum; persistence failure must preserve old recovery points.
- Situation: consuming an append-only event log incrementally. Signal: multiple rows can share the same timestamp, so a timestamp-only cursor can permanently skip rows created at the cursor boundary. Response: advance delivery with a unique monotonic key such as the database row ID; retain timestamps only for display or interval gating, and regression-test rows inserted before and after a poll with identical timestamps. Expected payoff: at-most-once cursor progression without same-timestamp data loss.
- When retiring legacy TUI cursor state, trace every renderer, keyboard handler, background event, and mouse path first; replace reachable behavior with typed AppState views before deleting the old block.

Signal: command contracts and dispatcher cases exist while keyboard and mouse provide no explicit action. Response: add a shared render/hit-test layout and bind only visible controls to the existing authenticated command path with snapshot-scoped idempotency. Expected payoff: operational controls without UI geometry drift, duplicate side effects, or authority bypass.

- Situation: a supervised daemon (systemd `Restart=on-failure`) silently stops and never comes back. Response: stop `aiosd` (release its open connection) before running `sqlite3 workspace.db "VACUUM;"` directly, then restart it; do the forced reindex pass *before* `VACUUM`, not after, so the vacuum only has to run once. Expected payoff: DB size actually reflects current content instead of accumulating monotonically regardless of what gets deleted from disk.

Expected payoff: respects a deliberate safety boundary instead of working around it, and the user's own terminal history ends up with a record of what got deleted.
